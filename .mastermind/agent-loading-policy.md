# Pro_Code Agent Loading Policy

This file tells Mastermind and coding agents how to load the doctrine strand safely.

## Load Order

1. `README.md` — public orientation
2. `CODER-SKILL.md` — coding identity and execution principles
3. `STYLE.md` — naming, commit, and style rules
4. `LINK-LIBRARY.md` — ecosystem map and repo pointers
5. `REPO-AUDIT.md` — audit discipline
6. `.apex/repo-profile.json` — hidden repo role profile
7. `.helix/strand.json` — double helix strand declaration
8. `.helix/inheritance-contract.md` — inheritance rules
9. `.links/repo-registry.json` — hidden pointer registry

## Mastermind Rules

- Treat this repo as doctrine authority.
- Propose changes on a branch; do not rewrite `main` directly.
- Prefer additive contracts over destructive edits.
- Use pointers instead of duplicating large docs.
- Never commit raw secrets, tokens, privileged records, or private evidence.

## Output Contract

When Mastermind audits this repo, it should emit:

- drift findings
- broken link findings
- outdated doctrine findings
- proposed patches
- verification notes

All findings belong in `.audit/` or a branch/PR until accepted.
